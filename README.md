# 飞书现场课逐字稿整理 Skill

这个 Skill 用于把“课程群里的 PPT 照片”和“飞书会议逐字稿”自动整理成一份可边听边看的飞书云文档。

## 安装

需要 macOS、Ruby、Swift，以及已经完成配置和登录的 `lark-cli`。

```bash
git clone https://github.com/zhengzhentao86/feishu-live-course-transcript.git \
  ~/.codex/skills/feishu-live-course-transcript
```

如果目录已经存在，更新到最新版：

```bash
git -C ~/.codex/skills/feishu-live-course-transcript pull --ff-only
```

重新打开 Codex 会话后即可调用。首次使用时，Skill 会自行检查依赖、登录状态和最小权限。

## 安装后第一次怎么用

1. 对 Codex 说“检查飞书现场课整理环境”。Skill 会检查 lark-cli、登录状态、权限、Ruby 和 Swift；缺少 lark-cli 时会先说明安装内容，得到你确认后再安装。
2. 新建一个飞书群，把用于整理课程的飞书账号加入群。
3. 上课前开启飞书会议和实时转写。Skill 会先验证群、会议事件和字幕样本；如果需要智能体独立入会，会明确检查该开关。
4. 对 Codex 说：

   > 使用飞书现场课逐字稿整理：课程叫《×××》，群叫“××课程群”，讲师是××。确认把群内 PPT、会议转写和讲师名写入新的飞书文档，从现在开始整理。

5. 上课时按讲解顺序把 PPT 拍到群里即可。每条新图片消息都会写入；没有新图片时，新增讲解仍会持续追加为纯文本。
6. 课程结束后，对 Codex 说“课程结束，完成最终整理”；Skill 会保留实时工作稿，并另建一份按主题分章的正式成品稿。

### 没有 lark-cli 时

Skill 会先运行环境预检，不会直接报一串命令错误，也不会静默安装：

- 默认只告诉你缺什么、为什么需要、将安装到哪里；
- 你明确同意后，才会通过国内 npm 镜像把 `@larksuite/cli` 安装到 `~/.local`，不使用 sudo；
- 安装后继续引导应用配置、飞书扫码登录和最小权限授权；
- 每一步完成后重新检查，全部通过才开始读取课程群和创建云文档。

## 每次调用都会提醒什么

Skill 会先显示四条简短指引：建群、开会议转写、按顺序拍 PPT、默认新建文档。提醒之后才读取飞书并开始整理。

## 默认输出标准

- 每堂课新建一份飞书云文档；
- 连续多张 PPT 默认按 OCR 与讲解语义拆成“一段相关讲解 + 一张图”；只有共享讲解无法可靠拆分时才保留一次正文并把图片最多四列并排；
- 没有新 PPT 时仍按时间连续写入精修会议文本，直到会议结束；
- 课中默认每 2 分钟检查一次，把 2–6 分钟新增内容合成一个批次；
- 确定性路由器会让空轮询直接退出；普通文字用 Terra low，普通图文用 Terra medium，复杂收尾才用 high；
- 模型只读取本批 compact context，不读取完整群历史、完整会议、完整文档或 processed ID 数组；
- 群消息从 `last_message_scan_end` 继续（旧状态回退上次消息时间），并用 `last_message_position` 本地过滤；会议事件从 `last_transcript_end_time` 或事件游标继续，不从开头拉取；
- 群消息列表关闭 reactions 补查，只批量下载新增图片，新图才 OCR；
- 每轮所有新增内容整批一次写入、一次尾部局部回读，不重复扫描历史图片；
- 删除口水词、逐字重复和课堂杂项，但保留原讲解顺序、解释、案例与问答，不改成摘要；
- 每个新条目保存课程原文并做忠实度校验；正文保留率至少 80%，230 字只限制单个自然段，内容多就拆段；
- 重点概念蓝色加粗；
- 第一轮从课程开始时间建立群图片全量清单，之后不重复扫描历史图片；不做 OCR 相似度去重，同页重拍仍保留；
- 每次增量写入都有 revision 检查和图片资源回读；
- 正式妙记校正、主题章节生成、整章资源检查和首中尾视觉验收只在整门课结束后执行一次。
- 连续换会使用同一个课程时钟，不从 00:00:00 重新开始；历史缺口触发成品重建，不往尾部追加“补全”章节。
- 旧会话升级到 v4 后，长 processed ID 会迁移到本地索引文件，并自动保留 v3 状态备份。
- 旧会话若没有尾部锚点，课前单独运行 `scripts/migrate_session_v3.rb`；迁移不进入日常轮询。
- 课程结束后的妙记校正用 `scripts/mark_minutes_corrected.rb` 绑定妙记来源、校正批次和最终 revision，再做一次完整验收。

## 推荐拍摄习惯

- PPT 切换后稍等 1—3 秒再拍，尽量拍全页面；
- 讲师讲到该页核心内容后再发送，晚 30—90 秒没有问题；
- 同一页拍糊了可以重拍；两张都会保留，如不希望保留糊图，请不要发送或在写入前撤回；
- 不要把闲聊截图或无关照片发到指定课程群；
- 多位老师时，开课前告诉 Codex 每个时段的讲师姓名。

## 常用说法

- 新课：`用飞书现场课逐字稿整理，群是“新品课”，讲师王老师，默认新建文档。`
- 新课并直接授权：`用飞书现场课逐字稿整理，群是“新品课”，讲师王老师；确认把群内 PPT、会议转写和讲师名写入新的飞书文档。`
- 已知群 ID：`用 Skill 整理 chat_id=oc_xxx 的课程，讲师王老师，会议 ID=xxx。`
- 临时换老师：`从 15:30 开始讲师改为李老师。`
- 手动收尾：`课程结束，读取正式妙记，补齐并验收文档。`
- 指定旧文档：`不要新建，追加到这份飞书文档的“第二天下午”章节。`

## 运行前提

- macOS；
- `lark-cli` 已安装并以用户身份登录；
- 飞书账号对目标群、会议、妙记和目标云文档有权限；
- 本地可运行 Ruby 和 Swift；
- 课程期间 Codex 桌面任务或其他承载自动任务的进程保持运行。

如果需要电脑关机后仍持续整理，应把同一流程部署到常驻服务器或飞书机器人；本 Skill 默认面向当前电脑上的 Codex 自动任务。

## 开发与发布

- `evals/` 是本机私有评测集，不进入公共仓库；它可能包含用于回归测试的课程语料。
- 公共仓库只同步 Skill 说明、脚本、资源、许可证和安全说明。
- 维护者可运行 `ruby scripts/install_github_auto_sync.rb` 安装 macOS 自动同步任务；任务默认每 5 分钟检查一次，只做普通提交、拉取和推送，永不强制推送。
- 每次自动提交前都会运行 `ruby scripts/check_publication_safety.rb --staged`。发现本地绝对路径、飞书链接、疑似凭证或私钥时会停止同步。
