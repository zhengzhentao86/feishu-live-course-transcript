# 课后整理：PDF、妙记、录音与录像

目标是把已有课程素材还原为完整的图文对照逐字稿。直接盘点资料，不要求用户重新建群或开会。最终执行 `finalization.md`，格式遵循 `style-standard.md`。

## 1. 素材盘点与输入路由

先区分每份资料的角色：参考成品、正式课件、原始逐字稿、会议摘要、录音、录像。参考链接用于学习格式；摘要用于定位课程和关联源，不能替代原始发言。

| 可用素材 | 处理方式 | 仍缺什么 |
|---|---|---|
| PDF + 妙记（有逐字稿和录像） | 原 PDF 逐页配图，逐字稿精修，录像校时并补实操截图 | 可按完整图文流程完成 |
| PDF + 妙记（仅文字 / 音频） | 语义对齐页码与发言，图片采用 PDF | 实操可保留文字；没有画面不能承诺截图 |
| PDF + 录音 | 录音生成带时间的逐字稿，语义匹配 PDF | 对齐时间标为估计，不能当成已确认的翻页时间 |
| 妙记 / 录像，无 PDF | 从录像截取清晰 PPT 和实操画面，配原始转写 | 无法取得画面时报告实际缺口 |
| 只有录音 / 原始逐字稿 | 忠实精修纯文本；已有相关照片可另行对齐 | 图片缺失不阻止整理正文，不生成假截图 |
| 只有 PDF / 只有会议摘要 | 先核对页数、准备原页及索引，或定位关联的逐字稿 | 请求补充原始发言；不得以扩写摘要 / 课件冒充逐字稿 |
| 历史课程群照片 + 转写 | 建完整照片清单，按发送时间、课程时间及语义对齐 | 不启动实时轮询；照片发送时间只是辅助证据 |

记录课程名称、来源、时长、页数、讲师映射、各录制的时间基准、可用音视频轨道及缺口。用户已提供的信息直接使用；只问会影响内容归属或阻塞完成的问题。缺一个素材时继续完成不依赖它的部分。

课后按实际素材检查依赖和权限：先定位 `lark-cli` 并检查登录，再按需要读写的文档 / 妙记 / 媒体请求最小权限。课中 `preflight.rb` 的群、会议事件、Swift 必需项不能成为纯文本课后任务的阻塞。只有实际需要 OCR 才检查 Swift / 可用 OCR；只有本地渲染才检查 PDF 运行库。先探测命令和 import，不默认存在某个 Python 包；需要安装时优先国内镜像，使用任务依赖目录。

## 2. 原始资料只采集一次完整快照

- 飞书文档、Wiki、会议纪要：通过 `lark-cli` 读取，找到关联妙记或原始逐字稿链接；只有摘要时继续定位转写，不开始凭摘要扩写。
- 妙记：按当前 CLI 帮助与可用 `lark-minutes` 指引调用 `minutes +detail`，显式请求 `--transcript`，章节按需请求。完整响应与原文落盘，后续本地处理；不反复下载整份逐字稿。确有未就绪 / 来源更新时记录原因和版本后再取。
- 录像：通过 `lark-cli minutes +download` 下载可用媒体，确认含视频轨道后才安排截图；只取得音频时如实走无录像分支。不能用浏览器抓取飞书画面绕过 CLI。
- 本地录音 / 录像需要转写时：先说明上传飞书处理，沿用已授予的素材处理授权；标准链路是 `lark-cli drive +upload` 取得文件 token → `minutes +upload` 生成妙记 → `minutes +detail` 取逐字稿。执行前读取对应可用的 `lark-minutes` / `lark-drive` 指引及命令帮助。用户明确要求仅本地处理时尊重该限制，另择被授权的转写方案，不暗中上传。
- 身份沿用来源身份；拒绝访问不靠换账号绕过。命令具体参数以当前 `--help` 为准，不能把某次版本的响应形状视为永远固定。
- 原始资料落盘后记录路径、来源 ID、版本 / 获取时间及文件摘要。不要把用户原文或真实链接写入 Skill。

## 3. 原页渲染与录像补图

1. 以 PDF 总页数建立完整页码清单，逐页渲染为清晰图片；保持页面比例和完整内容。默认用约 1500 像素以上宽度作为起点，按小字可读性调整。文本提取 / OCR 只用于页标题、关键词和匹配索引。
2. 核对 PDF 与录像是否为同一版本。正式 PDF 的层叠对象或动画终态与录像不同，保留 PDF 原页；需要说明中间态时另加真实录像截图，不擅改课件。
3. 有录像时先查看代表画面，识别共享屏幕、演讲者布局、全屏切换等。不同布局分别确定截图范围，不能沿用上一门课的固定裁切坐标。裁切只去除无关边框，保留工具名称、操作输入、关键按钮与结果。
4. 长录像可从约每 5 秒粗采样开始，再在疑似翻页或缺页窗口细查。匹配保留至少前三候选及分数，结合页序、OCR 和前后转写。对缺页、重复页、近似相邻页和短暂页面局部逐秒或更细抽查，前页 / 本页 / 后页并排核对；不能只信 Top-1。
5. 建实操候选清单，重点找“打开工具—输入内容—操作设置—执行—输出结果—报错与修正”等有信息变化的画面。每个有实质变化的步骤选清晰关键帧，紧邻对应原话；不要为了图片数量截取大量相同画面。
6. 所有 PDF 页都要有去向。已确认展示的标页码和时间；无法确认展示的保留原页并标“录像未确认展示”，按课件顺序放在相关章节或课件附页处，不编精确时间和发言。真正缺失 / 无法读取的页面登记原因。

图片清单至少包含：`image_id`、`kind=pdf_page|video_slide|practice|group_photo`、原始来源、PDF 页码或录像秒数、文件路径、语义标题、关联转写 ID、对齐依据、`alignment=visual_confirmed|semantic_estimate|unconfirmed`。PDF 页码、群图顺序、实操图编号分开，不能把实操截图编号成“正式 PPT 第 N 页”。

## 4. 先建时间轴，再精修正文

- 将原始转写解析成稳定 ID、来源 ID、原始起止时间、课程起止时间、原始说话人、`source_text`。多场录制记录各自 offset，维持统一课程时间；明确时间零点是原录像开始还是课程开始，不静默重置或扣除休息。
- 按连续时间的小段精修，通常 1–3 分钟证据条目。长课可按约 5000–6000 字原文分批给模型，保留边界上下文；不能把整门课交给模型概括后再补图。
- 优先采用局部精修决策：排除项 `{source_id, reason}`，替换 `{source_id, old, new}`，高亮 `{source_id, text}`，以及章节 / 实操候选。确定性应用到原文；替换原句必须在指定来源中准确且唯一命中，不命中、跨段或重叠冲突先修正，不能静默跳过或全局替换同名内容。
- 原文始终保留。保存正文与来源映射，进行 80% 保留率、75% 顺序依据检查；可复用 `scripts/transcript_fidelity.rb`，但要显式适配字段，不能把缺失字段当作通过。数字过关后仍核对案例、条件、问答和因果链。
- 可辨识的首次示例视频台词如有教学价值，应保留并标明来源；无新增信息的重复播放、休息、调试和无法确认的噪声可列明排除。不可确认几句不代表整段案例都能删除。忠实转录不因整理者对课程观点的判断擅自删除有信息的原话。
- 同一来源片段恰好保留或排除一次；如需拆分，创建不重叠的子片段和原文偏移映射，避免多页重复正文。

## 5. 课后状态与交付

课后使用独立状态，不冒充正在进行的会议。推荐最小记录：

```json
{
  "schema": "course-post-class-v1",
  "mode": "post_class",
  "status": "preparing",
  "course_title": "课程名",
  "time_basis": "recording_start",
  "source_manifest": "sources/manifest.json",
  "canonical_content": "canonical-content.json",
  "image_manifest": "image-manifest.json",
  "exclusions": "excluded.json",
  "coverage": "coverage.json",
  "publication_state": "publication.json"
}
```

原始素材、原文、精修决策、配图依据、排除清单、覆盖表和发布状态均在课程工作目录中。状态可按 preparing → aligning → finalizing → completed 推进；实际完成前不写 completed。

按 `finalization.md` 完成主题编排、共同成品排版、分批发布与验收。交付飞书成品链接及本地可恢复稿，报告课程时长、正文规模、PDF 页数、补图数量、有效时间窗覆盖与未解决缺口。没有证据支持完整时说明缺口，不用“完整对照版”掩盖缺失。
