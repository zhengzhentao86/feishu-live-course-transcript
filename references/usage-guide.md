# 使用指引：两种整理方式

## 课后整理

可以直接说：

> 用课后整理模式，把这份 PDF 和飞书妙记整理成 PPT 图片、实操截图与逐字稿对照文档，按我认可的格式排版。

也可以提供录音、录像或历史课程群照片。先区分参考成品与原始素材：参考用于版式，原始转写用于正文。PDF 采用原页；没有 PPT 的实操从可用录像截图。没有录像则保留实操文字，只有 PDF 时先准备课件并请求补充原始发言，不编逐字稿。

不需要重新建群或开会。默认整理成新的飞书文档；只有明确要求追加时才复用旧文档。详细输入组合见 `post-class-workflow.md`。

## 课中整理

1. 建飞书课程群，并把用于整理的已登录账号加入群。
2. 开飞书会议并开启实时转写。
3. 提供课程名、群名、讲师名。Skill 解析群和当前会议，检查真实字幕样本，然后创建工作文档。
4. 上课时按讲解顺序把 PPT 拍进群；没有新照片，新增讲解也会继续整理。
5. 整门课结束时说“课程结束，完成最终整理”。保留实时工作稿，另建按主题编排的正式成品，与课后整理使用相同格式。

示例：

> 用课中整理模式，课程是《新品课》，群是“新品课程群”，讲师王老师。确认把群内 PPT、会议转写和讲师名整理进新的飞书文档，持续整理到课程结束。

- 只给群名：从账号可见群中解析；有同名候选才询问。
- 只说当前会议：自动发现；多个进行中会议才请用户选择。
- 给群 ID / 会议 ID：直接使用，不重复询问。
- 没有讲师名：可查候选，但共用设备账号或拍摄者不能直接当讲师；身份确实影响归属时确认映射并持久保存。
- 中途换会 / 换讲师：保留课程时间零点和文档，更新场次及映射；单个会议结束不代表课程结束。

## 指引与授权只说必要的部分

首次简述当前模式、使用哪些资料和输出位置，说明指定课程素材将写入飞书云文档。本地录音需要上传生成妙记时也说明。已有明确授权直接记录并执行；恢复、自动增量、同课收尾不重复确认，也不每次重发建群和开会指引。用户要求“先计划后确认”时遵守该节奏。

## 课中增量节奏

- 持续整理时默认每 2 分钟检查，合并 2–6 分钟新增内容作为一个云端批次。
- 第一轮从课程开始建立完整群图片基线，之后才只采增量；不按 OCR 相似度静默删除同页重拍照片。
- 群消息完整查询与位置游标规则以 `live-workflow.md` / `hot-path-contract.md` 为准，不能仅用扫描结束时间过滤晚到图片。
- 只对新增图片下载、OCR；每批一次写入、一次尾部回读。没有增量时静默。
- 课中普通轮不读正式妙记、不做全文验收和首中尾预览。整门课结束后采集一次正式转写快照并生成成品。
- 用户请求持续整理时使用当前任务心跳；课后一次性任务不建心跳。普通更新保持安静，完成、失败或需要用户行动时再通知。

## 环境准备

所有飞书操作用 `lark-cli`。首次或环境报错时检查命令、登录和本次所需权限。课中可运行 `ruby scripts/preflight.rb`，再按 `live-workflow.md` 做课程预检；课后依素材做最小检查，不要求群 / 实时会议 / Swift 一律齐全。

- 缺少 lark-cli：说明将从国内 npm 镜像下载 `@larksuite/cli` 并写入 `~/.local`；已有安装授权则沿用，未授权才确认。课中安装辅助入口是 `preflight.rb --install-lark-cli --yes`，不使用 sudo。
- 未配置 / 未登录 / 缺少 scope：按 CLI 输出引导配置与最小权限授权，展示原始链接和二维码；授权恢复后重新验证。
- 资源本身不可读：说明具体权限缺口，不通过浏览器或换身份绕过。
- 本地 PDF 渲染、OCR 和截图工具按实际需要检查；纯音频课后整理不因缺少图片工具而阻塞。

## 推荐拍摄习惯

- 翻页后等画面稳定，尽量拍全页面；发送时间允许略晚于讲解，配对仍结合语义。
- 模糊可重拍；课中每条照片默认保留，不想保留的照片在写入前撤回。
- 指定课程群尽量只发课程相关图片；有多位讲师时告知时段或换人节点。

最终验收与成品格式统一见 `finalization.md`、`style-standard.md`。
