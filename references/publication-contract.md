# 两种模式共用的成品发布合同

此文件仅在最终发布和异常恢复时读取。飞书操作全部通过 `lark-cli`。输入是课程目录中的成品 XML、图片清单和来源映射；不依赖直播字段。按当前 CLI 文档 / 帮助确认命令与响应，不使用浏览器替代。

## 发布前

1. 本地素材、正文、页序、图注和覆盖先验收，生成最终 XML 及可恢复的本地稿。保持图片路径相对于实际执行目录有效，图片名称唯一。
2. 保存 XML 摘要与分批计划。一批不超过 60 个顶层块 / 8 张图片，可采用 55 块 / 6 图留余量；必须统计嵌套 grid 内图片。单节点已经超限时先拆分，不允许一个过大的单元穿过批次上限。
3. `publication.json` 原子保存文档 ID、URL、revision、已验证尾锚点、`last_chunk`、`pending_chunk`、阶段、已验证图数和输入摘要。开始写入后成品摘要变化必须停止，不能沿用旧断点写新内容。

## 每批执行与验证

- 第 0 批创建新的文档；后续批次以已验证 revision 追加。一次写入后只回读该批一次：首批读取文档，后续以旧尾锚点到结尾进行 range fetch。完整读取省略 scope，不能传不存在的 `--scope full`。
- CLI 调用保留退出码、stdout、stderr；从两路识别带顶层 `ok` 的结构化 envelope。未知响应、明确错误、警告或部分成功不能折叠为空结果继续。
- 创建返回的 canonical 文档 ID 可能在 `document_id`，也可能需从包装节点定位；拿到 ID、URL 后先落盘，不能只因未命中旧 token 字段再次创建。
- range XML 可能以 `fragment` 包装。旧尾锚点在 grid / column 内时，确认它是首个返回容器最后一个带 ID 的后代，再去掉旧容器核对新增后缀。新尾锚点取新增内容所有带 ID 后代中的最后一个。
- 逐项核对本批块顺序、正文内容、图片数量、名称、顺序和资源。图片名允许请求逻辑名或上传文件 basename 的已知归一化，保存云端实际名；每张都必须含非空 `token/src/url/href`。
- 图注仅在确认差异全部是末尾实际换行或转义换行时允许归一化后严格比较。不得改变正文、标题、页码、数字或中间字符来“修复”差异；保留原始回读证据。
- 图片更新可能增加多次内部 revision，不能要求只加 1。核对云端 revision 不倒退，追加相对旧 revision 已推进；配合旧尾锚点和精确新增后缀验证。发现无关编辑、锚点漂移、未知修订则停写。
- 验证成功先原子保存 `last_chunk/revision/tail`，再进入下一批。

## 不确定结果的恢复

创建或追加前保存 pending 状态。请求超时、解析失败或验证失败，先检查落盘响应与已保存回读：

- 已完整落地：仅提交经核验的本地状态，从下一批继续，零重复云写入。
- 创建结果不确定：按精确标题和最近创建时间用 `lark-cli docs +search` 找唯一候选，再 fetch 核对首批内容、图片和 ID。无法唯一确认则停止，不重建同名文档。
- 追加结果不确定：围绕旧尾锚点核对该批后缀。只有确认未落地且 revision / 锚点仍可信才允许重试；不能把验证脚本错误当成云端没有写入。
- revision 或内容冲突：保留 XML、批次、响应、回读和状态，先解决冲突，不覆盖、不强制刷新 revision 继续。

正常批次回读快照可复用。最终只取一次当前成品全量快照验收；若只是本地校验器问题，修好后复用同一证据，不重复上传或整份读取。`published` 只代表发布完成，完成 `finalization.md` 的内容和视觉验收后才是 `completed`。
