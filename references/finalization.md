# 共同成品流程：课后直入，课中结束后进入

两种模式最终使用相同的阅读格式。课后在源资料齐备、原文精修和图片对齐后进入；课中先依 `live-workflow.md` 判断课程结束，完成最后增量和正式妙记校正后进入。不要对课后任务要求群 ID、进行中会议、实时字幕样本或心跳记录。

## 1. 固定来源与内容

从本地 canonical 内容生成成品，不在工作文档尾部追加“补全 / 回填”章节。已有实时工作稿保留为过程记录。检查来源片段恰好保留或排除一次，原文、排除理由、图片页码和对齐依据可追踪。

课后的输入协议见 `post-class-workflow.md`；课中的输入是 v5 `content_groups` 与 `accepted_slides`。将两者转为共同的渲染输入：有序正文段落及来源 ID、有序图片及来源类型、主题章节边界、讲师映射、时间基准。时间估计与视觉确认分别标注，未确认的图片不强填时间。

## 2. 按知识段划章，保持正文原顺序

模型只看各时间片段的简短索引和已有主题候选，输出章节标题与有序来源 / group IDs；不重写正文。章节按完整知识段和课程节奏组织，不按每页 PPT 建一级标题，也不固定章数。用户指定约 10–30 分钟一章时遵守；否则以实际主题完整性为先。

每个已保留条目恰好出现一次，章节和正文不逆序。标题描述课程内容，不出现“第一段、补全、回填、图片补全、系统修复”等处理痕迹。

## 3. 渲染成品

完整细则见 `style-standard.md`。按以下结构生成飞书 XML 和本地可恢复稿：

1. 课程标题；课程信息区含日期、讲师、原始录制时长、实际课件页数和补图数，来源链接按实际可用情况列出。
2. 简短阅读说明：精修范围、时间零点、来源区别、未确认图片或发言身份等实际限制。
3. 主题章节；章内连续自然段，适度显示时间定位；原 PDF 页 / 群内照片 / 实操图就近配文，重点蓝色加粗。

渲染用课程工作目录中的确定性脚本把已核验正文和图片编排为文档，模型不再整稿重写。保持源数据与展示事件分离：内部细粒度时间和来源 ID 不因为展示合并而丢失。图片只改变位置不复制讲解，主题合并不改变正文内容。

**现有脚本兼容边界：** `build_final_outline_context.rb`、`render_final_document.rb`、`publish_final_document.rb`、`validate_session.rb` 是旧 v5 直播成品实现，含固定章数、逐组时间标签、直播字段或旧 CLI 响应假设，不能直接用于本版共同格式。可复用其忠实度、转义和图片解析逻辑；新任务在工作目录按本合同生成和校验。不为复用旧脚本而伪造直播状态、增加密集时间标签或将实操图称为正式 PPT。`complete_session.rb` 同样依赖旧 v5 验收，新的成品记录应在下述验收全部通过后再更新完成状态。

## 4. 本地验收先于发布

- 逐条忠实度通过：保留率 ≥80%，顺序依据 ≥75%；每自然段不超过 230 个中文字符。核对解释、例子、数字、条件、因果和问答。
- 所有来源 ID 恰好保留或排除一次，正文不重复；排除清单有理由且没有以“摘要化”掩盖删减。
- 至少两小时课程按 5–10 分钟建立覆盖表。按片段起止区间与窗口的交集计算，不只按片段开始时间归桶；长原文需细分再核对，每窗有一小段文字不代表整个窗口覆盖。每个有效讲解区间有正文去向，未知空窗未解决不得宣称完整。
- PDF 全页清单有去向；课中所有已接收照片有去向，不以相似度静默去重；实操图可追溯原录像时间。核对数量、页序、重复、文件可读性及未确认项。
- 同一主题连续讲解不因每张图重复时间标签；图注紧邻相关内容；没有把“同一张图配多段话”压缩成一段摘要。

## 5. 分批发布与云端验收

按 `publication-contract.md` 通过 `lark-cli` 分批创建新成品。用户明确指定旧文档时才复用，并先核对位置和 revision。

发布完成后，保留一次当前成品的全量回读快照，用它核对：正文与本地稿相符、主题章节和顺序一致、图片总数 / 类型 / 顺序 / 名称 / 图注符合清单、每图都有真实资源、内容没有重复或丢失。正文验证针对本地最终稿，不能只查关键字或标题；内部每条时间不要求全部展示。

通过 `lark-cli` 下载成品首、中、尾图片并实际打开查看。存在实操图时，另外核对至少一张实操截图的输入 / 界面 / 结果可读性；近似相邻页与短暂页还要查看其局部匹配证据。只有一两张图时看所有图；纯文字稿图像项记为不适用，不能伪造视觉通过记录。

记录验收 revision、正文规模、素材覆盖、实际图片数、视觉查看结果、缺口与所用证据。失败保留成品候选、XML、快照和发布断点，修复具体问题，不降低门槛、不重复全量发布。

## 6. 完成与交付

以上全部通过后记录 `status=completed`、成品 URL / ID / revision 与验收报告。课中有本次课程心跳时停止后续检查，课后没有心跳就无需创建或处理自动任务。

向用户给出成品链接，简述原始时长、正文规模、PDF 页数、实操补图数量及实际缺口。内部日志和排除清单留在本地备查，不将私有内容复制进 Skill。内容确有缺失时清楚写明，不能只用“已完整整理”结束。
