# 精修和排版标准

## 固定结构

每个图文组使用以下顺序。正文可以有多个自然段，并可紧跟 1—N 张连续图片；多张图片共用一次时间戳和正文，禁止复制正文：

```xml
<p><b>王老师 · 00:18:42</b></p>
<p>我们先判断商品属于哪一种经营场景，再选择对应的 <b><span text-color="rgb(36,91,219)">AI 工具组合</span></b>。不同场景的问题不一样，不能拿同一套工具硬套。</p>
<p>工具也不是越多越好。先把输入、生成、审核和复盘接起来，跑出一个闭环，再判断哪一步值得继续加工具。</p>
<img path="@./runs/.../slide-1.jpg" width="780" caption="PPT｜群内发送 15:47｜课程约 00:18:42｜AI 工具组合"/>
<img path="@./runs/.../slide-2.jpg" width="780" caption="PPT｜群内发送 15:48｜课程约 00:18:42｜工具落地步骤"/>
```

没有新增图片时使用纯文本结构：

```xml
<p><b>王老师 · 00:20:10–00:21:36</b></p>
<p>企业落地不能从工具清单开始，而要先明确 <b><span text-color="rgb(36,91,219)">业务问题和验收指标</span></b>。问题定义清楚后，再决定工具、流程和责任人。</p>
```

## 去口水词

可以删除：

- 呃、啊、然后呢、就是、对吧、好不好；
- 连续两遍以上的同义表达；
- “能看到吗”“声音怎么样”等课堂设备调试；
- 与该页内容无关的点名、签到、寒暄；
- 已被下一句完整重说的残句。

必须保留：

- 原观点及其条件和边界；
- 数字、时间、比例、步骤、工具名、案例名；
- “为什么”和“所以”之间的因果链；
- 讲师明确表达的不确定性或限制；
- 重要示例及结果。

不能删除或概括掉：

- 为了说明一个结论而展开的案例背景、推演步骤和具体例子；
- 讲师先提出问题、再分析、最后回答的过程；
- 近义但新增了条件、角度或证据的复述；
- 课程相关的学员提问和讲师回答。

判断方法：删除后如果读者只知道“结论是什么”，却不知道“为什么、怎么做、例子是什么”，说明删多了。

## 忠实精修与摘要的边界

错误做法：把 10—20 分钟讲解整理成一段高度概括的结论，即使结论正确，也不再是逐字稿。

正确做法：按 1—3 分钟的自然讲解窗口连续整理。只删没有信息的口头填充，保留讲师的原句顺序、例子、解释、转折和结论。单个自然段超过 230 字时拆段，不删信息；同一张 PPT 可以对应多个连续自然段。

每个 batch 条目必须保存课程相关原文 `source_text`，并通过 `scripts/validate_fidelity.rb`：

- 精修正文相对原文的字符保留比例不低于 80%；
- 至少 75% 的精修正文字符能够按原顺序在原文中找到；
- 高密度课程原文达到 160 字时，单条时间跨度不得超过 3 分钟。

校验只是底线。即使数值通过，也要人工确认案例、数字、条件、因果链和讲解节奏没有丢失。

## 重点高亮

batch 文本用 `[[重点]]` 标记，追加脚本转换为蓝色加粗。每段通常 1—4 处：

- 方法名：`[[四层公式]]`
- 关键结论：`[[先判断场景，再选择工具]]`
- 重要动作：`[[输入—生成—审核—复盘]]`

不要高亮连接词、整段文字或普通人名。

## 字数与语气

- 每个图文组可含 1—N 张连续图片，可以包含多个自然段；没有图片的新增讲解按语义边界写成独立纯文本条目；
- 每个自然段不超过 230 个中文字符；内容多时增加段落或拆分连续条目；
- 保持口语可读性，但去掉散乱和重复；
- 保持原讲解密度，不把逐字稿改写成摘要；
- 不增加讲师未讲过的知识；
- 工作稿和成品都使用整门课程的连续相对时间 `HH:MM:SS`；续场换会不重新归零；
- 工作稿图片说明必须含群发送时间、课程时间和语义化标题；成品图片说明使用连续正式页码、课程时间和语义化标题；
- 主题章节使用学员可读的“主题｜具体内容”标题，不出现补全、回填、第一段、第二段、图片补全或系统处理痕迹。
